# 开项 · 项目启动表单

把人和 AI 要做的事分开：人在表单里定下产品定位、业务与功能、专项设置、约束与偏好，生成一份项目简报交给 AI 开发。简报写明哪些事人已决定、哪些交给 AI、哪些还没决定，以及按什么阶段交付和验收。可选调用本机 Codex 生成项目级 `AGENTS.md` 草案。

## 在线使用

网址：https://lzq-teach.github.io/dingxinglizi/

- 不用安装，打开即用。填写内容只保存在你自己的浏览器里，不会上传。
- 网页版不能「生成 AGENTS.md」（需要调用你电脑上的 Codex），其余功能都能用。
- 每次合并到 `main`，网站会自动更新（`.github/workflows/pages.yml`）。首次使用需要仓库主人在 Settings → Pages 把 Source 设为「GitHub Actions」，然后在 Actions 里重新运行一次「Deploy to GitHub Pages」。

## 在本机运行

要「生成 AGENTS.md」，需要在你的电脑上启动一个小服务，再用浏览器打开。只需要 Python 3，不依赖第三方包。

1. 启动服务（窗口保持打开，关掉窗口服务就停了）：
   - **macOS**：双击 `启动表单.command`
   - **Windows**：双击 `启动表单.bat`
   - 或在仓库根目录运行 `python3 server.py`（Windows 上是 `py server.py`）
2. 浏览器打开 http://127.0.0.1:8767/

看到「无法访问此网站 / ERR_CONNECTION_REFUSED」说明服务没在运行，回到第 1 步。端口可用环境变量 `KICKOFF_PORT` 修改。

> 不能直接双击 `web/index.html` 打开：浏览器出于安全限制，不允许本地文件加载页面脚本，页面会是空白。

## 使用说明

1. 依次填写五步：**产品定位 → 业务与功能 → 专项设置 → 约束与偏好 → 项目简报**。专项设置会根据前面的选择显示相关问题。
2. 必填项随「交付目标」变化，越接近上线，开发前要定下的越多：

   | 交付目标 | 必填 |
   |---|---|
   | 所有项目 | 产品类型、交付目标、业务目标 |
   | 交互原型 | 核心流程、页面清单 |
   | 系统 Demo | 核心流程、数据对象、验收场景 |
   | 上线版本 | 核心流程、数据对象、业务规则、典型输入与预期结果、验收场景 |

3. 选项里的「待推荐 / 待估」表示交给 AI 推荐或估算；「待定 / 待确认」表示你还没决定。
4. 项目简报页的「需要你决定」列出会影响业务、成本、权限或范围的问题，逐条写下决定，或点「交给 AI 决定」。页面顶部显示交接状态，全部定下后显示「可以交给 AI」。
5. 复制简报、导出 Markdown 或备份 JSON。简报包含：

   - **人已决定**：AI 必须遵守的约束
   - **交给 AI 决定**：AI 开工前给出选择和理由，等人确认
   - **还没决定**：AI 不得自行假设，开工前必须先问
   - **需要人准备**：账号、资质、接口等 AI 无法代办的事
   - **开发阶段**：每个阶段做什么、怎么验收；AI 做完一个阶段就停下等验收
   - **给 AI 的工作规则**

6. 选择「生成 AGENTS.md」会调用本机 Codex 使用的模型，占用该账户的额度：
   - 需要本机已安装并登录 Codex CLI，无需单独 API 密钥。
   - 生成时读取 `~/.codex/skills/focused-delivery/SKILL.md`，项目文件引用原路径以避免复制后过期。
   - Codex 或 skill 不在默认位置时，用环境变量 `KICKOFF_CODEX`、`KICKOFF_SKILL` 指定路径。
   - 生成中不重复调用，失败可重试；修改表单后需重新生成才能下载。
   - 生成结果是草案，可编辑后下载。放入新项目根目录使用；已有 `AGENTS.md` 应先合并，进行中的开发会话须显式重新读取。

默认效率优先：先寻找并验证成熟方案，再做最小改造；「开发方式」可指定局部或重点定制。

表单和生成草案保存在当前浏览器（localStorage），换设备或清理浏览器前请用 JSON 备份。表单选项调整后，旧草稿里已停用的选项会被移除并提示，其余内容保留。

## 目录结构

```
.
├── web/                 # 前端页面（纯静态，无需构建）
│   ├── index.html
│   ├── app.js           # 页面交互、草稿保存、导入导出
│   ├── model.mjs        # 表单字段、必填规则、人机交接与简报生成规则
│   └── styles.css
├── server.py            # 本机服务：提供页面，并调用 Codex 生成 AGENTS.md
├── tests/               # 表单逻辑与本机服务的测试
├── 启动表单.command      # macOS 双击启动
├── 启动表单.bat          # Windows 双击启动
├── .github/workflows/pages.yml # 合并到 main 后发布 web/ 到 GitHub Pages
├── .openai/hosting.json # 静态托管配置（发布 web/ 目录）
└── LICENSE
```

## 测试

```bash
node --test tests/model.test.mjs          # 表单逻辑：必填规则、人机交接、旧草稿兼容、简报内容
python3 -m unittest discover -s tests -v  # 本机服务：来源限制、并发限制、错误返回
```

## 开发约定

- `main` 为主分支，新功能和修复在独立分支上开发，通过 Pull Request 合并。
- 提交信息写清楚改了什么、为什么改。
- 文件统一使用 UTF-8 编码、LF 换行，缩进规则见 `.editorconfig`。
- 本仓库是公开的：密钥、令牌写在 `.env` 中（已被忽略），不要提交。
